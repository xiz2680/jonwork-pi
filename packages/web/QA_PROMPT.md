# Herdr 测试工程师验证提示词

你是本项目的独立高级测试工程师。请只验证，不修改业务代码；发现缺陷时记录复现步骤、实际结果、预期结果、严重级别和证据。项目目录是 `/Users/a/xz-workspace/pi`，验证分支是 `codex/web-workbench`，测试地址是 `http://127.0.0.1:4318`。

## 验证目标

验证 Jonwork Pi Web 对话工作台是否达到可发布测试标准，重点确认界面不是静态演示稿，所有当前里程碑内的可见功能都有真实行为。

## 环境准备

1. 检查当前分支和工作区状态，不得覆盖已有修改。
2. 执行 `npm run check`。
3. 执行 `npm test --workspace=@jonwork/pi-web`。
4. 如果 4318 端口没有服务，执行 `npm run start --workspace=@jonwork/pi-web -- --host 127.0.0.1 --port 4318`。
5. 检查 `GET /api/health`，必须返回 `ok: true`，且 Pi 构建存在时 `pi` 为 `available`。

## 必测用例

### A. 身份与初始状态

- 页面不得显示演示账号“王 / mrwang”。
- 未接企业认证时必须显示“本地用户 / 未登录”。
- 首次打开显示空会话，不得伪造历史消息、运行进度或权限请求。
- 停止任务按钮在空闲状态不可用。

### B. 新建会话

- 点击最近对话标题旁的“＋”。
- 必须调用 `POST /api/session/new` 并由 Pi RPC 执行 `new_session`。
- 成功后显示“已创建新会话”；Pi 不可用时必须返回 503，禁止创建模拟会话。
- 中央区域、标题、任务状态、计时、进度和权限卡必须恢复空闲状态。
- 最近对话增加“新对话”，不能只清空输入框。

### C. 真实 Pi 对话

- 输入“只回复：新会话功能正常”并发送。
- 页面必须立即出现本地用户消息。
- Pi 返回内容必须流式显示为 Jonwork 消息，最终包含“新会话功能正常”。
- 运行中发送按钮切换为停止行为，结束后恢复。
- 面向用户的连接状态必须显示“服务正常”，不得暴露 Pi、RPC、CLI、供应商或凭证等实现细节。

### D. 对话工具栏

- 图片附件：接受 PNG/JPEG/WebP，最多 4 张；选择后显示文件名，发送后清空。
- 设计模式：点击后有明确状态反馈。
- 模型：点击后从 `/api/state` 获取并显示真实当前模型，不得硬编码。
- 深度思考：开启时后端应先发送 `set_thinking_level: high`。
- 语音：支持的浏览器能启动识别；不支持时必须给出明确提示。
- Enter 发送、Shift+Enter 换行。
- 输入框默认保持紧凑，长文本自动增高，发送后恢复默认高度；焦点态只能有一层清晰外框，不能出现内部矩形描边。

### E. Pi 运行面板

- 执行过程、产出结果、相关资源三个标签可切换，选中状态正确。
- 三个标签必须包含一致风格的图标、清晰选中面和动态数量徽标，不得只是无层级的文字链接。
- 停止任务调用 `/api/abort`；重试会产生真实新请求。
- Pi 的 `extension_ui_request` 能显示确认信息，并把用户选择以 `extension_ui_response` 回传。
- 查看完整参数可展开和收起。
- 移动端能够关闭和重新打开运行面板。
- 底部停止与重试按钮必须对齐、同高、图标规格统一；运行、完成和禁用状态层级明确。

### F. 其他控件

- 分享复制当前地址；失败时给出明确提示。
- 已实现的结果图支持放大和关闭。
- 快捷建议能写入输入框。
- 未开发的侧栏模块必须显示“规划中”并说明不在当前里程碑，不能伪装成已实现页面。
- “产出结果”和“相关资源”的数量与内容必须来自当前会话，初始值为 0；不得出现固定的 3、8 或咖啡机样例。
- 请求设计图时，只有真实图像工具产出才能展示图片；图像能力未配置时必须明确说明，不得声称已经生成。

### G. 异常与安全

- 空提示返回 400。
- 超过 5 MB 请求被拒绝。
- 非法静态文件路径不能越权读取。
- 检查 CSP、`X-Content-Type-Options`、`Referrer-Policy` 和 `Permissions-Policy`。
- 记录 `npm audit --omit=dev` 的已知上游风险，不得把它误报为本 Web 包新增依赖。
- 浏览器控制台不得有未处理 JavaScript 错误。

### H. 响应式与可访问性

- 验证 1920×1080、1366×768、390×844。
- 输入框、发送、菜单、运行面板必须可达，不能被遮挡。
- 关键按钮具备可访问名称；Tab 键可到达主要交互。
- 文本和控件不应溢出或重叠。

## 输出格式

输出一份 Markdown 测试报告，必须包含：

1. 结论：通过 / 有条件通过 / 不通过。
2. 环境、分支、提交 SHA、测试时间。
3. 用例表：编号、结果、证据。
4. 缺陷表：严重级别 P0–P3、复现步骤、实际结果、预期结果。
5. 自动化命令的完整结果摘要。
6. 桌面端和移动端截图路径。
7. 已知风险与是否允许进入测试环境。

如果发现任何 P0/P1，结论必须是不通过。不得因为界面看起来正确就判定功能通过；必须验证网络请求、Pi RPC 状态和最终界面结果。
